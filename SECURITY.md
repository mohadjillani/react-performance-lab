# Security

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting on this repository (Security → Report a vulnerability) rather than a public issue.

## Scope

This is a measurement lab, not a service. The application serves a fixed, synthetic dataset (`lib/data/fixtures.json`, generated from a seed) through read-only route handlers; there is no user input that reaches storage, no authentication, and nothing is deployed from this repository.

Two things are worth knowing if you run or fork it:

- **The `compare` workflow writes to `main`.** Its merge job has `contents: write` so it can commit the regenerated `docs/results.md`. It only ever runs on `workflow_dispatch` and a schedule from this repository's own `main`, never on pull requests, so a fork's code cannot reach that token. Keep it that way if you add triggers.
- **SVG thumbnails.** The fix that moves images to `next/image` serves the category SVGs through the image optimiser, which requires `images.dangerouslyAllowSVG`. The configuration on that branch also sets a `Content-Security-Policy` and `contentDispositionType: 'attachment'` for optimised images, as the Next.js documentation recommends, because SVG can carry script. The SVGs themselves are generated by `scripts/seed.ts` and contain no script.

## Dependencies

`main` deliberately depends on `moment`, `lodash` and `recharts` at the top level of client components — that is the baseline the fix branches improve on. They are current releases; the lab's point is their weight, not their safety. Dependabot alerts apply to every branch equally because every branch shares `main`'s lockfile.
