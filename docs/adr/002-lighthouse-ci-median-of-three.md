# ADR 002: Lighthouse CI in GitHub Actions with median-of-three

**Status:** accepted · **Date:** 2026-08-29

## Context

Core Web Vitals numbers have to come from somewhere. A laptop gives the best numbers and the least reproducible ones: nobody else can re-run it, and the same laptop gives different numbers with a browser open. GitHub Actions runners are slower and noisier, but anyone with the repository can trigger a run and download the raw reports.

Lighthouse itself offers two throttling modes. Simulated throttling records an unthrottled trace and replays it through a network and CPU model; applied throttling actually slows the connection and CPU. Simulated is the default and is much less sensitive to whatever else the machine is doing.

## Decision

- **Lighthouse CI (`@lhci/cli`) runs in GitHub Actions** on every push to `main` and `fix/**` (`measure.yml`, the budget gate) and across all branches on demand and weekly (`compare.yml`, which regenerates `docs/results.md`).
- **Three runs per URL, median per metric.** `numberOfRuns: 3` in `.lighthouserc.js`, `aggregationMethod: 'median'` for assertions, and `scripts/lib/lighthouse.ts` reduces the raw reports the same way for the table.
- **Simulated throttling with Lighthouse's mobile defaults**, performance category only.
- **Budgets carry a documented tolerance** (see [methodology](../methodology.md)): score −5, LCP/TBT +20 %, CLS +0.02, bytes +10 %.
- **Raw reports are uploaded as workflow artifacts** so a reviewer can open the Lighthouse HTML behind any number in the table.
- `npm run measure` runs the identical pipeline locally, so the local and CI numbers differ only by machine.

## Consequences

- Reproducibility is preferred over precision. A number in the table can be regenerated by anyone; it cannot be regenerated exactly.
- Three runs is the smallest sample with a median. It costs about 90 seconds per route per branch on a runner; five would be a better estimator and was judged not worth the doubling.
- A single noisy run can still fail the gate when a metric sits near its budget. The tolerance is set to make this rare, not impossible; the fix is to re-run, and the workflow can be re-run from the Actions tab.
- Scores in `docs/results.md` are lower than a local run and drift a few points between regenerations. The table caption records where and when it was produced; only the deltas down a column are meant to be read.
